================================================================================
  1. OVERVIEW
================================================================================

OmniQuery lets users ask questions about any website, YouTube video, or
uploaded document and receive instant, context-grounded answers. It uses a
Retrieval-Augmented Generation (RAG) approach to ensure that every answer is
backed by real source material and is not hallucinated.

Core idea:
  User provides a source (URL / YouTube link / File)
  + asks a question
  → System ingests, chunks, embeds, retrieves, and generates an answer.

================================================================================
  4. RAG PIPELINES — DETAILED BREAKDOWN
================================================================================

Each pipeline follows the same 6-step pattern but with a source-specific loader.

4.1  WEB PIPELINE (feature/web/)
---------------------------------
  Step 1 — Load     : webLoader.py scrapes the given public URL
  Step 2 — Chunk    : chuncking.py splits text using LangChain text splitter
  Step 3 — Embed    : embed.py generates embeddings via Gemini (gemini-embedding-001)
  Step 4 — Store    : chromaDB.py persists vectors to db/web_chroma
  Step 5 — Retrieve : Similarity search (k=3) on the stored vectors
  Step 6 — Generate : response_generator.py sends context + question to Groq LLM

  Orchestrator     : web_main.py → web_pipeline(url, question) → answer string

4.2  YOUTUBE PIPELINE (feature/vid/)
--------------------------------------
  Step 1 — Load     : yt_loader.py extracts transcript via youtube-transcript-api
                      Also extracts video_id from the URL for per-video collections
  Step 2 — Chunk    : chunking.py splits transcript into smaller segments
  Step 3 — Embed    : embed.py generates embeddings via Gemini
  Step 4 — Store    : chromaDB.py saves to a per-video ChromaDB collection
                      (collection name: youtube_{video_id})
  Step 5 — Retrieve : Similarity search (k=3) on the video-specific collection
  Step 6 — Generate : response_generator.py sends context + question to Groq LLM

  Orchestrator     : yt_main.py → youtube_pipeline(url, question) → answer string

4.3  DOCUMENT PIPELINE (feature/doc/)
---------------------------------------
  Step 1 — Load     : doc_loader.py supports 14 file formats using LangChain loaders:
                        PDF         → PyPDFLoader
                        DOC/DOCX    → UnstructuredWordDocumentLoader
                        PPT/PPTX    → UnstructuredPowerPointLoader
                        XLS/XLSX    → UnstructuredExcelLoader
                        CSV         → CSVLoader
                        TXT/LOG     → TextLoader
                        JSON        → JSONLoader
                        MD          → UnstructuredMarkdownLoader
                        HTML/HTM    → UnstructuredHTMLLoader
  Step 2 — Chunk    : chunking.py splits loaded document pages
  Step 3 — Embed    : embed.py generates embeddings via Gemini
  Step 4 — Store    : chromaDB.py persists to db/doc_chroma
  Step 5 — Retrieve : Similarity search (k=3)
  Step 6 — Generate : response_generator.py sends context + question to Groq LLM

  Orchestrator     : doc_main.py → doc_pipeline(file_path, question) → answer string

================================================================================
  5. API ENDPOINTS
================================================================================

Base URL: http://localhost:8000

  METHOD   ENDPOINT               CONTENT TYPE         DESCRIPTION
  ------   --------               ------------         -----------
  GET      /api/health            —                    Health check (returns {"status":"ok"})
  POST     /api/query/web         application/json     Query a website URL
  POST     /api/query/youtube     application/json     Query a YouTube video
  POST     /api/query/document    multipart/form-data  Query an uploaded document

Request Bodies:
  /api/query/web & /api/query/youtube:
    {
      "url": "<URL string>",
      "question": "<question string>"
    }

  /api/query/document:
    Form fields:
      file     — the uploaded document (max 50 MB)
      question — the question about the document

Response Format (all endpoints):
    {
      "answer": "<generated answer with follow-up questions>",
      "source": "web" | "youtube" | "document"
    }

================================================================================
  6. LLM PROMPT STRATEGY
================================================================================

The response generator uses a grounded-answer prompt template:

  - Answer ONLY from the provided context
  - If information is not available in context, say so explicitly
  - After answering, generate 2–3 follow-up questions that:
      • Are answerable from the given context
      • Do not introduce topics outside the context
      • Are concise and curiosity-driven

This ensures hallucination-resistant, context-faithful answers.

================================================================================
  9. HOW TO RUN
================================================================================

Prerequisites:
  - Node.js >= 18
  - Python >= 3.10
  - Google AI API key (Gemini embeddings)
  - Groq API key (LLM inference)

Backend:
  cd server/python
  python -m venv .venv
  .venv\Scripts\activate          (Windows)
  pip install -r requirements.txt
  # Create .env with GOOGLE_API_KEY and GROQ_API_KEY
  python app.py                   → runs on http://localhost:8000

Frontend:
  cd client
  npm install
  npm run dev                     → runs on http://localhost:3000
